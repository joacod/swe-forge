# SWE Forge v0.1.0-alpha.1

SWE Forge is an experimental, opt-in workflow layer for AI coding harnesses.
This release establishes the first public compatibility snapshot and the
installer/evidence safety boundaries.

## Highlights

- `SOLO`, `SUBAGENTS`, and `ISOLATED` topology guidance.
- `GUIDED` and opt-in `PR` delivery modes.
- Registry-driven adapters for Pi, OpenCode, Claude Code, Codex, and Cursor.
- Transactional installation, verification, lifecycle inspection, and safe
  update/uninstall behavior.
- Executable validation evidence and compact receipts with optional routing
  metadata.

## Upgrade or install

Use a tagged source checkout rather than mutable `main`:

```bash
git clone --branch v0.1.0-alpha.1 --depth 1 \
  https://github.com/joacod/swe-forge.git ~/tools/swe-forge
cd ~/tools/swe-forge
scripts/swe-forge install pi --global
scripts/swe-forge verify pi --global
```

For an existing managed installation, run `version`, `status`, `doctor`, and
then `update <harness>` after reviewing the source tag. Legacy installations
without a managed manifest must be recreated before destructive lifecycle
operations are available.

## Compatibility

See [the compatibility snapshot](../compatibility.md). The release was locally
validated with Pi 0.84.1, OpenCode 1.18.16, Claude Code 2.1.37, and optional
Herdr 0.8.0. Codex and Cursor use the shared Agent Skill projection and were not
installed in the validation environment.

## Known limitations

- Alpha behavior and adapter compatibility may change.
- Pi is global-only and global installations are source-linked.
- Isolated execution requires demonstrated native worktree support or the
  optional Herdr provider; Herdr is not installed automatically.
- SWE Forge creates a PR in PR mode but never merges it or publishes releases
  automatically.

Please use the [real-run report template](https://github.com/joacod/swe-forge/issues/new?template=real-run-report.md)
to report friction, unnecessary ceremony, and useful evidence.
